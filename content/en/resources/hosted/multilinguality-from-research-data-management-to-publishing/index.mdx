## Learning outcomes

After completing this training resource, learners should be able to:

* Know the strategies, tools, and standards to manage multilingual research data
* Plan multilingual research data in order to improve findability and visibility of language diversity
* Publish and disseminate multilingual research

This module is accompanied by examples, reflexive activities and concrete use cases related to multilingual projects.

## 1. Know the Strategies, Tools and Standards to manage Multilingual Research Data

**Introductory context**

A research dataset typically contains data about entities and/or relations between entities. If your goal is to make your research dataset readable in several languages, you do not need to translate the names of the entities you describe to other languages. You would rather choose to describe these entities using a Uniform Resource Identifier (URI), which enables you to retrieve multilingual labels (and more), and use these as entity descriptor, instead of literal values (names). If you start from an existing dataset containing literal values instead of identifiers, you can use tools like [OpenRefine](https://marketplace.sshopencloud.eu/tool-or-service/hpBfcf) for finding the URI you need.

In the following, we give main recommendations for which sources for web identifiers to choose, together with examples. Clicking on the URI, you get to lists of multilingual entity labels (and more information). If you use a Linked Data database software, you can import all these labels (together with any other information found in these sources) into your own database environment.

### 1.1 Open Source Wikimedia tools and platforms for multilingual purposes 

[Wikimedia tools](https://en.wikipedia.org/wiki/Wikimedia_movement#Content_projects) are interoperable and multilingual from the start, enabling the integration of researchers' content and data in the semantic web to expand research impact beyond Academia.

[MediaWiki](https://www.mediawiki.org/wiki/MediaWiki) is a multilingual documentation platform with advanced collaborative features that is used by Wikipedia and the other Wikimedia tools.

Wikibase is a set of MediaWiki extensions that enables the use of semantically organized data. This suite supports the [Wikidata](http://wikidata.org/) platform.&#x20;

It can also be used by researchers with no maintenance costs in a [cloud service](https://www.wikibase.cloud/). Researchers may create Wikibase.cloud service instances to host their own documentation and data and connect it to Wikidata, functioning as an indexer hub, enabling federated queries with organizations like GLAM (Galleries, Libraries, Archives and Museums) institutions ([GLAM cultural heritage](https://en.wikipedia.org/wiki/GLAM_\(cultural_heritage\))).

</Figure>

Wikisource is the digital library for hosting texts in public domain and creative commons licences. It integrates powerful OCR (Optical Character Recognition) and HTR (Handwritten Text Recognition)  tools (free credits within Wikisource) to enable digital publishing and content linking.

[Wikipedia](https://www.wikipedia.org/) uses an encyclopedic, simpler language and may be used to reference researchers publications. An interesting academic extension activity is to promote editathons in the language of target communities and reach wider publics.

#### Set of recommendations and examples

1. Use a database solution that provides a multilingual user interface

[Wikibase](https://marketplace.sshopencloud.eu/tool-or-service/ETC9Ld) is a set of extensions to MediaWiki, which is available in 215 languages. [Translations are crowdsourced](https://translatewiki.net/), you can contribute. To learn more about Wikibase, visit [DHwiki Wikibase](https://marketplace.sshopencloud.eu/tool-or-service/tuV3dg). Wikibase supports URI natively, in a way that users see entity labels in their preferred language, while, under the hood, the entity is represented by a web identifier, which is the same for all its labels, in all available languages.

2. Do not use literal values (names) for representing entities, and make use of established Linked Data identifiers instead.&#x20;

Choose identifiers that lead to human readable labels in multiple languages. [CESSDA](https://marketplace.sshopencloud.eu/tool-or-service/TxIgnX) (Consortium of European Social Science Data Archives) lists vocabularies that contain such multilingual identifiers. A general source for multilingually labelled identifiers for entities of all domains is Wikidata. 

**Examples:**

* Instead of “Edinburgh”, use [http://www.wikidata.org/entity/Q23436](http://www.wikidata.org/entity/Q23436) or [https://www.geonames.org/2650225](https://www.geonames.org/2650225) 
* Instead of a literal like “nominative”, or items in a Linked Data vocabulary that has no multilingual labels for most of the entities it describes (see [LexInfo](http://www.lexinfo.net/ontology/3.0/lexinfo#nominativeCase)), use [http://www.wikidata.org/entity/Q131105](http://www.wikidata.org/entity/Q131105) or [http://www.lexinfo.net/ontology/3.0/lexinfo#nominativeCase](http://www.lexinfo.net/ontology/3.0/lexinfo#nominativeCase)
* Instead of “Torre di Pisa”, use [http://www.wikidata.org/entity/Q39054](http://www.wikidata.org/entity/Q39054) or [https://www.geonames.org/6269273](https://www.geonames.org/6269273)
* Instead of “The Buddha” use [http://www.wikidata.org/entity/Q9441](http://www.wikidata.org/entity/Q9441), instead of “Angela Davis” use [https://www.wikidata.org/wiki/Q160456](https://www.wikidata.org/wiki/Q160456) (or [https://viaf.org/viaf/108895419](https://viaf.org/viaf/108895419)) 
* For subject headings or content-describing keywords, instead of an English-centered vocabulary like LCSH, use Wikidata (e.g. “Archaeology”, [http://www.wikidata.org/entity/Q23498](http://www.wikidata.org/entity/Q23498) (see [in LCSH](https://id.loc.gov/authorities/subjects/sh85006507.html))
* For dates and time spans, use Wikidata (e.g. “20th century”: [http://www.wikidata.org/entity/Q6927](http://www.wikidata.org/entity/Q6927)), or PeriodO ([https://perio.do/en/](https://perio.do/en/))
* Not only for entities like the above, but also for a property or “relation”, instead of “born in” or “has birthplace” or a Linked Data vocabulary that has no multilingual labels (see this property e.g. [in schema.org](https://schema.org/birthPlace)) use [http://www.wikidata.org/entity/P19](http://www.wikidata.org/entity/P19)

3. Using URI (identifiers on the web) instead of literal values will, by the way, make your dataset ready for [Linked Data](https://www.wikidata.org/wiki/Q515701).

For sharing your research data as [Five-Star Open Data](https://5stardata.info), you should use W3C-recommended ontologies for modeling your data. For example, for lexical data, you would use [Ontolex-Lemon](https://en.wikipedia.org/wiki/OntoLex).

4. If a Wikidata entity misses a label in one of the languages you want to cover, just add it to Wikidata, so that it becomes available for everyone.
5. If you have a dataset containing literal values, you can use [OpenRefine](https://marketplace.sshopencloud.eu/tool-or-service/hpBfcf) for finding the corresponding identifiers, e.g. in Wikidata.

### 1.2 CLARIN Open Source tools for Multilingual Text Analysis

The Common Language Resources and Technology Infrastructure (CLARIN) platform is a digital research infrastructure that provides language data, tools, and services for researchers in the humanities and social sciences following FAIR principles. This platform is multilingual and supports low-resource and underrepresented languages. It maps Natural Language Processing tools to support text and analysis (e.g., Part of Speech, Named Entity Recognition, Open Large Language Models, dictionaries, parallel corpora). It actively supports projects like[ ](https://www.clarin.eu/content/industry-and-beyond)[LLMs4EU](https://www.llms4eu.eu/) to build open multilingual Artificial Intelligence models for underrepresented European languages.

The[ Language Resource Switchboard](https://switchboard.clarin.eu/) is the CLARIN tool that enables the language detection of uploaded resources and lists all compatible NLP tools available in the CLARIN repository.

The [Virtual Language Observatory](https://vlo.clarin.eu) (VLO) enables researchers to explore linguistic resources, services and tools available within CLARIN and related communities. Its aim is to provide an easy-to-use interface, allowing for a uniform search and discovery process for a large number of resources from a wide variety of domains and providers. 

## 2. Plan Multilingual Research Data

**Introductory context**

Making research data multilingual contributes to the implementation of the FAIR principles and supports more inclusive, accessible and equitable research practices. 

Research data are not produced in a linguistically neutral environment. Throughout the research lifecycle, researchers make decisions about which languages to use when formulating research questions, engaging with participants, collecting and interpreting data, collaborating with others, documenting research processes and sharing results. These decisions can influence not only how research data are communicated, but also how knowledge is produced, understood, recognised and reused.

Language is therefore not simply a means of accessing research data; it can also shape what those data mean, how they are interpreted and whose knowledge is represented.

For example, when data are collected in one language but analysed or documented in another, certain concepts, categories or culturally specific meanings may be transformed, simplified or lost through translation. Similarly, the decision to describe a dataset exclusively in English may increase its visibility within international academic infrastructures while limiting its discoverability and usability among the communities from which the data originated.

This highlights the importance of considering the linguistic dimensions of research data throughout their lifecycle, rather than treating multilingualism solely as a matter of dissemination.

Planning multilingual research data also means recognising that language choices are shaped by institutional expectations, disciplinary conventions, available resources and unequal relations of linguistic power. Not all languages enjoy the same levels of visibility, technological support or recognition within research environments. Consequently, decisions about which languages to include, prioritise or exclude may affect who can participate in research and whose knowledge becomes accessible or reusable.

Researchers should consider which communities may benefit from their data, which linguistic resources those communities use, and which elements of the research data require multilingual representation. These may include metadata, documentation, research instruments, terminology, variable descriptions, codebooks and other materials necessary for understanding and reusing the data.

Ultimately, planning multilingual research data is both a practical and a reflective process. It involves anticipating linguistic needs, identifying potential barriers and considering how language choices may enable or constrain participation in the production and reuse of knowledge.

### 2.1 Include Language Diversity in your Data Management Plan (DMP) and use Descriptive Metadata

In your DMP, include your outputs and data in the language of the country of study to make sure it’s accessible and visible to the local communities, and ensure inclusivity (avoid research extractivism). You have to make sure your research process is aligned with [CARE ](https://www.gida-global.org/careprinciples)principles.

In your DMP, translate your researcher profile into the language of the community you will be working with.

Using descriptive metadata is key to ensure findability of research data. For content indexation, libraries use controlled vocabularies instead of freely chosen keywords. The Library of Congress Subject Headings (LCSH) are a widely used controlled vocabulary for that purpose. The use of Linked Data enhances multilinguality. 

**Example:**

If you use Wikidata ID instead of LCSH terms as descriptors for your content, these descriptors are accessible using labels in multiple languages. ### 2.3 Take into account [CARE](https://www.gida-global.org/careprinciples) principles in your DMP

Collective Benefit and Authority to Control is most of the time enabled by providing key research processes and results documentation in the language of the community that is being studied.

* For digital content that is culturally sensitive, researchers may use a baseline license from [Creative Commons](https://creativecommons.org/): Creative Commons Attribution-Non Commercial-No Derivatives (CC BY-NC-ND)
* For signaling cultural sensitive and communicate community-defined protocols for its use, researchers may use [Traditional Knowledge Labels - TK Labels](https://onlineacademiccommunity.uvic.ca/scholarlycommunications/2022/08/08/tk-labels-indigenous-peoples-assert-sovereignty-knowledges/)
* To ensure openness does not compromise collective benefit, consider adopting Less Open Equity-based Licenses - [NOODLE](https://openfuture.eu/publication/noodl-an-experiment-in-equitable-data-licensing-promise-and-limits/) 

Implementing licenses and practices that align with CARE principles to ensure community-centric control may also imply using the community’s own hardware and human maintenance infrastructure. Linked open data ecosystems like Wikidata, Wikibase.cloud, and Wikimedia Commons and other public infrastructure operate under very strict open licensing frameworks that strictly enforce FAIR principles. The [Very Small GLAM](https://meta.wikimedia.org/wiki/Very_Small_GLAM) project describes the implementation of Wikimedia-based tools on-premise. Even if an on-premise setup may be ideal as a sovereign solution, it may still require too many resources. A sub-optimal alternative may be to use other [hosting services](https://dhwiki.wikibase.cloud/wiki/Structure_and_features_of_Wikibase_for_DH#Wikibase%20Hosting%20Solutions).

### 2.4 Sociolinguistic approach of multilingual research

Planning multilingual research data therefore involves more than translating datasets or metadata after research has been completed. It requires recognising linguistic diversity as an integral dimension of research data management from the outset.

This is particularly relevant when research involves communities whose languages differ from those predominantly used in academic institutions, scientific publications or research infrastructures. If a researcher's target community communicates in a different language, members of that community should, wherever possible, be able to discover, access, understand and reuse the research data in ways that are linguistically meaningful to them.

Communities that currently lack the institutional, financial or technical resources to conduct similar research independently may nevertheless possess valuable linguistic, cultural and contextual knowledge that enables them to interpret, enrich and reuse existing data. Providing multilingual research resources can help create opportunities for these communities to engage with research findings, develop new applications and contribute to further knowledge production.

**Example:** This is an example of a linguistically inclusive project and live corpus of underrepresented languages: “[*Creole Connections*](https://www.creoleconnections.cahss.ed.ac.uk/interactive/)*. An interactive research project”*.
