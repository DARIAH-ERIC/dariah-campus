## Introduction to Organisation, Documentation & Metadata for Data Stewards

In this unit we  introduce the core practices that support high‑quality, reusable and interoperable research data—from foundational organisation and file‑naming conventions to documentation tools, open formats, metadata standards, and ontologies. It explains how each layer contributes to building FAIR‑aligned, long‑term usable datasets, and shows how linked data and semantic clarity emerge only when these earlier steps are in place. Through practical examples and guidance, the session highlights the crucial role of data stewards in enabling good data management and helping research teams move from simply “having data” to producing meaningful, discoverable, trustworthy research outputs.

The unit also introduces the concept of research reproducibility and its importance for research integrity and transparency through the experiences of Dr Dermot Lynott and Dr Brendan Palmer.&#x20;

## Learning Outcomes&#x20;

1. Apply effective file naming conventions and organise data using logical, discipline‑appropriate file structures.​
2. Compare a range of data documentation tools (e.g., README files, ELNs).​
3. Justify the value of open formats in relation to disciplinary practices and FAIR/OPEN principles.​
4. Identify and consider generic and domain‑specific metadata standards to ensure data is discoverable, reusable, and FAIR‑compliant.​
5. Consider the role of ontologies to enhance semantic clarity and support interoperability.​

Explain the core concepts of linked data and interoperability to improve data integration and long‑term usability.

<Callout kind="none" title="Self Reflection - Metadata & Documentation">
  **If You Left Tomorrow: Would Your Data Still Make Sense?**

  Imagine that tomorrow, you leave your role, you have won the lottery and you are off to live the dream and someone else must use your data without asking you any questions. As a newly minted millionaire you are no longer available to add context to the data you have left behind and are quickly forgetting. 

  Consider the following question:

  1. What would your replacement need to understand your dataset correctly?
  2. What documentation would be essential (e.g., README file, data dictionary, methodology notes)?
  3. What metadata elements would be critical to include?
  4. What risks arise for your project if documentation and metadata are incomplete?
</Callout>
